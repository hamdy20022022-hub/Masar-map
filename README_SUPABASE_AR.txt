مسار MASAR — نسخة لوحة التحكم المرتبطة بـ Supabase

محتويات مهمة:
- admin.html + admin-supabase.js: لوحة التحكم الفعلية، تسجيل الدخول عبر Supabase Auth، والتحقق من public.is_admin().
- supabase-config.js: إعدادات اتصال Supabase المستخدمة في الموقع ولوحة التحكم.
- supabase-policies.sql: سياسات RLS اللازمة لإدارة المواقع والصور والمحافظات والتصنيفات.
- supabase-public.js: يجعل واجهة الموقع تقرأ المواقع المنشورة من قاعدة البيانات عند إعداد الاتصال.
- index.html: الموقع العام.

التجهيز مرة واحدة:
1) من Supabase افتح Project Settings > API. انسخ Project URL و Publishable key (أو anon public key القديم).
2) افتح supabase-config.js واستبدل YOUR-PROJECT-REF و YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY بالقيم الحقيقية. لا تستخدم service_role أو secret key مطلقًا.
3) افتح SQL Editor في Supabase ونفّذ محتوى supabase-policies.sql مرة واحدة فقط. هذا الملف يعتمد على وجود public.is_admin() التي أنشأناها سابقًا.
4) ارفع جميع ملفات المجلد مع الحفاظ على ترتيب الملفات والمجلد assets إلى نفس استضافة الموقع. افتح admin.html.
5) سجّل الدخول ببريد وكلمة مرور حساب Supabase Auth الذي يطابق سجله في public.profiles وله role='admin'. لا تستخدم UID ككلمة مرور.
6) جرّب إضافة موقع سياحي باسم ووصف ومحافظة وتصنيف وإحداثيات ورابط صورة، ثم اختر «منشور». يجب أن يظهر في الموقع العام بعد ضبط config ورفع الملفات.

مهم:
- لا تضع service_role أو secret key في أي ملف HTML/JS أو في المتصفح.
- لوحة التحكم تستخدم قاعدة البيانات الحقيقية؛ لا تعتمد على رمز الدخول التجريبي القديم.
- أزرار إدارة المواقع وصورها تعمل من خلال Supabase. المحافظات والتصنيفات معروضة للاختيار، وتظل إدارتها اليدوية محدودة في هذه النسخة لتجنب إدخال أعمدة غير معروفة في مخطط قاعدة البيانات.
- عند تشغيل supabase-policies.sql لأول مرة فقط؛ إعادة تشغيل CREATE POLICY نفسه سيعطي خطأ بأن السياسة موجودة.
- إذا ظهر خطأ عند تسجيل الدخول، تأكد من أن المستخدم يستطيع تسجيل الدخول إلى Supabase Auth وأن public.is_admin() ترجع true داخل جلسة المستخدم.

خطوة واحدة إضافية في Supabase (مرة واحدة، وآمنة إن كررتها):
  افتح SQL Editor ونفّذ محتوى الملف  supabase-multi-images.sql
  هذا الملف يجهّز: القراءة العامة لصور المواقع، جدول صور الصفحة الرئيسية (site_images)، وحاوية رفع الصور masar-images
  (قراءة عامة، والرفع/الحذف للمدير فقط، بحد أقصى 10MB للصورة).

1) صور متعددة لكل وجهة
   لوحة التحكم > المواقع السياحية > إضافة/تعديل: في «معرض الصور» ارفع عدة صور دفعة واحدة (أو الصق روابط).
   الصور الجديدة تُرفع عند الضغط «حفظ». الزر ★ يعيّن الصورة كغلاف. تُضغط الصور تلقائيًا قبل الرفع.
   أو من تبويب «صور المواقع»: اختر الموقع ثم ارفع صورًا أو احذف منها.
   في الموقع: بطاقة الوجهة وصفحتها تقلّبان صورها تلقائيًا (مع أسهم ونقاط وصور مصغّرة وعرض مكبّر).

2) صور الصفحة الرئيسية
   لوحة التحكم > صور الصفحة الرئيسية: ارفع/رتّب/أوقف الصور وأضف عنوانًا قصيرًا لكل صورة. تتبدّل تلقائيًا في أعلى الموقع.
   إن لم تضف أي صورة يستخدم الموقع الصور الافتراضية الموجودة في data.js (heroSlides).

3) المواقع
   places-data.js يحتوي ~66 موقعًا إضافيًا موزعة على المحافظات الـ22 (طبيعية، تاريخية، ترفيهية، شواطئ، جبال، أودية، جزر، متاحف،
   أسواق، فنادق، صحراء) وكلها مرتبطة بـ Google Maps بالاسم. صورها مؤقتة؛ استبدلها بصور حقيقية من لوحة التحكم.
   المطاعم والفنادق وغيرها تظهر أيضًا مباشرة من Google Maps في صفحة كل فئة وفي صفحة كل محافظة.
   مواقع قاعدة البيانات تُضاف إلى هذه المواقع، وإن طابق اسمُ موقعٍ في القاعدة اسمَ موقعٍ مضمّن حلّ محله.
   لجعل قاعدة البيانات هي المصدر الوحيد ضع replaceBundled: true في supabase-config.js.

4) رقم التواصل يُضبط من data.js (contact) وهو الآن +967 780 788 105.
